# Sakshy

Website uptime checker/monitor: users define sites, a worker checks them, alerts on down/up.

- Design (draft, source of truth): `design/` — start with `architecture.md`.
- Backend: Python 3.14, FastAPI, SQLAlchemy, Pydantic, pytest. DB: PostgreSQL 18.
- Frontend: React + TypeScript. Email: Mailpit.
- Runs locally via Docker. Ignore deployment until the user raises it.
- `backend/` is a bare scaffold.
- Migrations: the initial one is hand-written from `design/schema.sql`; later ones are autogenerated, then reviewed.

## Plan (layered; each stage ships with its tests, no CI)
1. Foundation: compose (db, mailpit, emulator, api, worker, frontend), settings, ruff, type checker, pytest on real Postgres
2. Schema: Alembic initial migration, SQLAlchemy models, `migrate` service, constraint/isolation tests
3. Check engine: state machine, probe/evaluate, claim/lease, completion tx, heartbeat, shutdown, emulator
4. Alerts + housekeeping: outbox + sender, recipients, maintenance sweep, partitions, purge
5. API core + auth: cookie JWT, ownership (404), checks CRUD + pause/resume/run, health
6. API rest: groups, maintenance, stats/results/incidents, status pages (owner + public)
7. Realtime: NOTIFY → LISTEN → SSE
8. Frontend core: shell, typed OpenAPI client, auth, dashboard, check form/detail + charts
9. Frontend rest: groups, maintenance, status pages, public page, live updates
10. Wrap-up: e2e smoke, emulator load test, README (documented behaviours), seed data
